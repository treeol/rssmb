Key review findings folded in:
- **Migration bridge:** can't swap one module's import — `PlainRequest`/`PlainResponse`
  contain all command bodies in one type graph. Leaf types (dtyp, fscc) swap
  independently; the whole message tree swaps in one commit with explicit
  `From` conversions at the seam.
- **`binrw_util` is a hidden dependency:** PosMarker, sized/null wide strings,
  multi_sz — this machinery makes variable-length messages work. Not just
  Guid/FileTime/Boolean.
- **Full enum inventory:** `RequestContent` has Cancel, OplockBreakAck,
  LeaseBreakAck; `ResponseContent` has OplockBreakNotify, LeaseBreakNotify,
  OplockBreak, LeaseBreak, ServerToClientNotification, Error — more than
  the 14 initially listed.
- **Request bodies missing from initial inventory:** `CreateRequest` (create
  contexts — the hardest decoder), `SessionSetupRequest`, `TreeConnectRequest`,
  `ReadRequest`, `WriteRequest`, `FlushRequest`, `CancelRequest`,
  `TreeDisconnectRequest`, `LogoffRequest` (header-only? — confirm).
- **Error body:** `build_error_response` builds 9 bytes manually, but
  `ResponseContent::Error(ErrorResponse)` is also used for compound member
  errors (`dispatch.rs:560,592`). Both paths need the same type.
- **0x81 NetBIOS panic risk:** `copy_to_bytes(len)` without checking
  `buf.remaining()` first (`framing.rs:31`). Add to fuzz targets.
- **`no-default-features = true` is wrong Cargo syntax** — should be
  `default-features = false`. The `server` feature may not be applied
  correctly. Fix in 9.4.
- **smb-rs is MIT licensed** — vendoring with attribution is an option, but
  the decision is to write our own and use smb-rs as reference only.
- **Normative layout sources:** MS-SMB2, MS-FSCC, MS-TN3P (for DCE/RPC),
  and the patch (`patches/smb-rs-rssmb.patch`) as the record of every
  server-side fix. Map each patch hunk to a replacement test before deleting it.
- **Tests must come before removal, not after:** golden fixtures (committed
  smb-msg-generated byte vectors), differential testing crate, in-process
  harness, and `encrypted` live scenarios all precede the smb-rs removal.
- **LazyLock:** we don't use it; MSRV is determined by actual deps, not
  guessed.

The "Current state" lines were checked against the tree on 2026-10-12, with
file:line refs. Re-check them before starting, because line numbers drift.

## Context — why this step exists

smb-rs was meant as a **reference**, not a dependency. The original plan
(`rssmb-plan-draft.md:7-8`) says "builds on the wire-protocol knowledge from
smb-rs/ … but implements the server half from scratch." The reuse table below
that line (`:31-51`) contradicts this by depending on `smb-msg`, `smb-dtyp`,
`smb-fscc` as path deps. That table was never the intent.

Step 9 corrects this: replace the smb-rs dependency with our own protocol
crate (`rssmb-proto`), then remove `smb-rs/` entirely. smb-rs stays as a
reference we read, not code we link.

### 9.1 Create `rssmb-proto` — our own SMB2 message protocol crate

**Goal:** replace `smb-msg`, `smb-dtyp`, `smb-fscc` with one crate we own. Use
smb-rs as reference for the wire layout — read it, don't link it.

**Complete scope — what `rssmb-proto` must contain** (corrected after review):

1. **`binrw_util`** (from `smb-dtyp`, the hidden cost): `PosMarker` (offset
   tracking for variable-length fields), `FileTime` (u64 ↔ FILETIME),
   `Boolean` (1-byte bool), `sized_string`/`fixed_string` (null wide
   strings), `multi_sz`. Without this machinery, variable-length messages
   (SessionSetup buffer, TreeConnect path, Create name/contexts, Ioctl
   in/out, negotiate contexts) can't work in binrw. **This goes first.**

2. **`dtyp`** (leaf, swappable independently): `Guid` (16-byte struct,
   `new()`, `from_bytes`, `to_bytes`, `make_guid!` macro or `const`
   constructor, `From<[u8;16]>`, `Copy + PartialEq`), `FileTime`,
   `Boolean`.

3. **`fscc`** (leaf, swappable independently): `FileAttributes` bitfield,
   `FileBasicInformation`, `FileEndOfFileInformation`,
   `FileDispositionInformation`, `FileRenameInformation`,
   `FileFsSectorSizeInformation`, `SectorSizeInfoFlags`.
   Each needs `read_le` (SET_INFO decode) and `write_le` (QUERY_INFO encode).
   Also audit `fsinfo.rs` and `handle_query_info`/`handle_set_info`/
   `handle_query_directory` for raw numeric class matches and hand-encoded
   buffers that won't appear in a type import audit — produce a class matrix:
   **command/class → handler → request decoder → response encoder → fixture
   → expected unsupported behavior**.

4. **Header** (`smb_msg::header`): `Header` (64 bytes: ProtocolId,
   StructureSize, CreditCharge, **Status** (imported at `dispatch.rs:17`,
   missing from initial inventory), Command, CreditRequest, Flags,
   NextCommand, MessageId, **TreeId** (used extensively, missing from
   initial inventory), AsyncId, SessionId, Signature), `Command` enum
   (with `Display`), `HeaderFlags` bitfield (`.with_server_to_redir()`,
   `.related_operations()`, `.set_related_operations()`).
   `STRUCT_SIZE` const. `Header::read_le` / `header.write_le`.

5. **Plain request/response** (`smb_msg::plain`): `PlainRequest`,
   `PlainResponse`, `RequestContent` enum (full list from
   `smb-rs/crates/smb-msg/src/plain.rs`: Negotiate, SessionSetup, Echo,
   TreeConnect, Create, Close, Read, Write, Flush, QueryInfo,
   QueryDirectory, SetInfo, ChangeNotify, Ioctl, **Cancel**, **OplockBreakAck**,
   **LeaseBreakAck**), `ResponseContent` enum (all of the above response
   variants, **OplockBreakNotify**, **LeaseBreakNotify**, **OplockBreak**,
   **LeaseBreak**, **ServerToClientNotification**, **Error**).
   `read_le` / `write_le`.

   **This is the hard part — not "swap one module's import":**
   `PlainRequest { header: Header, content: RequestContent }` is one type
   graph. `RequestContent::Negotiate(NegotiateRequest)` embeds
   `NegotiateRequest`, which embeds `Guid`. You cannot swap `Header` to
   `rssmb_proto::Header` while `PlainRequest` is still `smb_msg::PlainRequest`
   — its `header` field is smb-msg's type. **The whole message tree swaps in
   one commit**, with explicit `From` conversions at the adapter boundary
   where needed during a temporary mixed state.

6. **Negotiate** (`smb_msg::negotiate`): `NegotiateRequest`,
   `NegotiateResponse`, `Dialect`, `NegotiateDialect`,
   `NegotiateSecurityMode`, `GlobalCapabilities`, `NegotiateContext`,
   `NegotiateContextType` (magic-tagged, `Unknown(u16)`, `.id()` method),
   `NegotiateContextValue` (with `Unknown`, `.get_matching_type()`),
   `EncryptionCipher` (with `Unknown(u16)`), `EncryptionCapabilities`,
   `HashAlgorithm` (with `Unknown(u16)`),
   `PreauthIntegrityCapabilities`, `SigningAlgorithmId` (with
   `Unknown(u16)`), `SigningCapabilities`, `CompressionCapabilities`,
   `CompressionCapsFlags`, `CompressionAlgorithm`. Helper methods:
   `get_ctx_preauth_integrity_capabilities()`,
   `get_ctx_signing_capabilities()`. `From<PreauthIntegrityCapabilities>
   for NegotiateContext`.

7. **Session setup** (`smb_msg::session_setup`): `SessionSetupRequest`
   (missing from initial inventory — carries the NTLM/SPNEGO blob),
   `SessionSetupResponse`, `SessionFlags` bitfield (is_null_session,
   is_guest, encrypt_data), `LogoffRequest` (confirm: header-only or has
   body?), `LogoffResponse`.

8. **Tree connect** (`smb_msg::tree_connect`): `TreeConnectRequest`
   (path), `TreeConnectResponse`, `ShareType` (Disk, Pipe), `ShareFlags`
   bitfield (encrypt_data), `TreeDisconnectRequest` (confirm: header-only?),
   `TreeDisconnectResponse` (currently `Default::default()`).

9. **Create / Close** (`smb_msg::create`): `CreateRequest` (**with create
   contexts** — MxAc, QFid, RqLs, DH2Q — the hardest decoder, needs
   saturating arithmetic on DataOffset/Length), `CreateResponse`,
   `CreateAction`, `CreateDisposition` (6 variants), `FileId` (persistent
   + volatile u64s, `Copy + PartialEq`), `CloseFlags` bitfield,
   `CloseRequest`, `CloseResponse`. `OplockLevel::None` from
   `smb_msg::oplock`, `OplockBreakAck`, `LeaseBreakAck`,
   `OplockBreakResponse`, `LeaseBreakResponse`, `OplockBreakNotify`.

10. **File I/O** (`smb_msg::file`): `ReadRequest` (offset, length, minimum
    count), `ReadResponse` (buffer field), `WriteRequest` (data offset —
    data extraction from raw frame), `WriteResponse` (count field),
    `FlushRequest` (confirm: header-only?), `FlushResponse`.

11. **Echo** (`smb_msg::echo`): `EchoRequest`, `EchoResponse`.

12. **Query info** (`smb_msg::info`): `QueryInfoRequest` (InfoType,
    FileInfoClass, OutputBufferLength, InputBuffer), `QueryInfoResponse`
    (buffer). Audit `handle_query_info` for all raw numeric class matches.

13. **Query directory** (`smb_msg::query_dir`): `QueryDirectoryRequest`
    (FileId, pattern, flags, class).

14. **Set info** (`smb_msg::info` or `smb_msg::set`): `SetInfoRequest`
    (InfoType, FileInfoClass, AdditionalInformation, InputBuffer).

15. **Ioctl** (`smb_msg::ioctl`): `IoctlRequest` (CtlCode, **FileId**
    (missing from initial inventory), InputOffset, InputCount,
    OutputOffset (not duplicated), OutputCount, MaxInputResponse,
    MaxOutputResponse, Flags), `IoctlResponse`.

16. **Change notify** (`smb_msg::notify`): `ChangeNotifyRequest`,
    `ServerToClientNotification`.

17. **Cancel** (`smb_msg::cancel`): `CancelRequest` (header-only? confirm).

18. **Error** (`smb_msg::error`): `ErrorResponse` (used in
    `ResponseContent::Error(ErrorResponse)` at `dispatch.rs:560,592` — not
    just the manually built body at `lib.rs:203-235`). **Both paths must
    use the same type.** The manual `build_error_response` builds 9 bytes
    (2 StructureSize + 1 context_count + 4 byte_count + 2 reserved); verify
    the typed `ErrorResponse` serializes to the same bytes.

**Method:** read smb-rs for the wire layout, write our own binrw-derive
structs. Don't copy code — understand the layout, write our own.

**Differential testing (while smb-rs is present):** a separate dev-only
crate (`rssmb-proto-diff`) that depends on both `smb-msg` and `rssmb-proto`,
with: (a) a committed corpus of real frames (impacket/cifs.ko/smbclient
captures), (b) decode-both/compare, re-encode-both/compare, (c) a
differential fuzz target (`smb_msg::PlainRequest::read_le(x)` vs
`rssmb_proto::…::read_le(x)` agreeing on Ok/Err and re-encoded bytes).
This only exists while smb-rs is present — it's the one window to catch
symmetric bugs. **Commit smb-msg-generated golden byte vectors as fixtures
now**, so post-removal tests aren't proto-vs-proto roundtrips (which pass
with symmetric bugs).

**Migration order (dependency-respecting):**
1. `binrw_util` + `dtyp` + `fscc` (leaf types, swappable independently)
2. Full message tree (header + all command bodies + plain enums) in **one
   commit**, with `From` conversions at the adapter boundary
3. Remove smb-rs (9.8)

**Per-module acceptance gate:**
1. Independent golden bytes or decoded semantic expectations for each
   migrated wire form.
2. Boundary/malformed-input tests: truncation, invalid sizes, count/length
   mismatches, offset overflow, overlap, alignment, unknown values,
   compound-member confinement.
3. Relevant signed/encrypted/compound live cases.
4. No unexplained differential mismatch with the patched reference;
   intentional fixes documented against the spec.
5. `cargo test --workspace` (all pass) + `run.sh` (incl. `encrypted`) +
   `mount.sh`.

**Size estimate:** ~13.5k lines in smb-rs (7.6k smb-msg + 3.1k smb-fscc +
2.8k smb-dtyp). Our subset is probably 60-70% of smb-msg (server needs both
directions of every command) + the fscc/dtyp we use. Likely 5-8k lines.
**[inferred — confirm by counting the actual types used before starting.]**

### 9.5 ID allocation

1. **TreeId**: per-session `next_tree_id: u32` counter starting at 1. Never
   0 or 0xFFFFFFFF.
2. **FileId**: per-connection, `volatile` from a per-connection counter,
   `persistent` random (`rand::random::<u64>()`). Never
   0xFFFFFFFFFFFFFFFF (the related-compound sentinel — check
   `substitute_file_id` still matches on the sentinel only).
3. **SessionId**: keep global (needs cross-server uniqueness for
   reconnect/multichannel later), but make it random non-zero with a
   collision check against the session table.
4. Remove `NEXT_FILE_ID` static.

**Tests:** TreeIds restart per session. FileIds never hit the sentinel.
persistent != volatile. Two connections can hold the same volatile id.
**Live:** impacket + `mount.sh` (cifs.ko compounds rely on related-FileId
substitution).

## Step 10 — Testing & conformance

Prerequisite: 9.0–9.4 (smb-rs gone, CI can build).

### 10.1 Make the server testable in-process

This should be done **before** 9.1's message-tree swap, not after — it
gives a fast in-process gate during the migration.

1. Add `listen_on(listener: TcpListener, state, shutdown)` in
   `connection.rs`. `listen`/`listen_with_state` call it. Test harness

2. `TestServer::start` returns the real port (drop the 100 ms sleep). Use

3. Builder: `TestServer::builder().share("public", guest_ok).user("alice",

4. Shutdown: explicit async `.stop().await` that joins tasks. `Drop` is
   best-effort cancellation, not the only cleanup guarantee.

**Verify:** smoke test — TCP connect, NEGOTIATE bytes, valid response.

### 10.2 Client-driven integration tests (`crates/rssmb-tests/tests/`)

**Driver:** impacket (Python), since the smb-rs `smb` client crate would
re-introduce an smb-rs dependency — exactly what we just removed. The
`crates/rssmb-tests` crate can shell out to `tests/live/client.py` or use
the `impacket` Python library via `tokio::process::Command` in CI. The
fast in-process tests use raw SMB2 bytes (we have the builders in
`rssmb-proto` now).

Two tiers:
- **In-process (Rust, `cargo test`):** raw-frame tests using `rssmb-proto`
  builders. Fast, no external deps. Covers: dialect negotiation, compound
  requests, file I/O round-trip, path safety, teardown handle release
  (counting VFS wrapper), sharing violations, malformed-input boundary
  tests. **Does NOT cover** authenticated signing/encryption — that needs
  a client-side NTLM+signing+GCM implementation. Leave authenticated flows
  to impacket.
- **CI (Python/impacket):** `tests/live/run.sh` in CI with all scenarios
  including `encrypted`. Covers real client behavior including auth.

### 10.5 Fuzzing

1. `cargo fuzz init` → commit `fuzz/` (nightly toolchain).
2. Targets (all `pub` entry points):
   - `parse_payload` (wire-adapter `framing.rs:63`)
   - `read_netbios_frame` (`framing.rs:15`) — **0x81 `copy_to_bytes` panic
     risk**; check `buf.remaining()` before `copy_to_bytes(len)`
   - `walk_compound` (`signing.rs:61`)
   - `decrypt_message` — target the **transform-header parse** before AEAD,
     or encrypt-then-mutate (random ciphertext alone mostly exercises tag
     rejection, which is low yield) (`crypto.rs:393`)
   - `extract_ntlm_token`, `extract_mech_types`, `extract_mech_list_mic`
     (`spnego.rs:23,58,278`) — **NTLM message parsing in `rssmb-auth` is
     the largest pre-auth attack surface**
   - `PduHeader::parse` + full `PipeState` write→read loop (`pdu.rs:103`)
   - `rssmb-proto` decode: `Header::read_le`, `PlainRequest::read_le`
   - Stateful: a `Connection` harness feeding arbitrary frame sequences
     into dispatch with an in-memory VFS (most valuable, most work — last).
     Check **timeouts, allocation amplification, hangs, state leaks** — not
     just panics. Feed authenticated mutated plaintext through encryption;
     random ciphertext alone exercises authentication rejection.
   - **Sanitize traffic corpora:** captures can contain credentials,
     authentication material, and file contents. Strip before committing.
3. Panic = finding. Fix at source, add crash input as regression test.
4. Seed corpora from real traffic (impacket/cifs.ko frame dumps).
5. CI: nightly job, ~5 min/target (smoke budget, not evidence of
   conformance), upload crashes as artifacts.
